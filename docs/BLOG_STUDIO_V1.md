# Hương Thiền Blog Studio — isolated experiment

Source base: Astro v2.0.5, production main commit 704c5c23a166e618426b8ff9b1be4fa4121ba200.

Status: Floot-prototyped independent CMS, with isolated PostgreSQL and email/password authentication. GitHub branch only contains integration blueprint; existing Astro production deliberately remains unchanged.

Floot application project: ac9b60b8-8e6e-418c-9714-5f21416444e2

## CMS schema

`blog_posts`: id, author_id, title, slug, language (`vi|en`), excerpt, content, category, cover_url, status (`draft|published`), seo_title, seo_description, created_at, updated_at, published_at. Composite unique index on (language, slug).

## API routes

- `GET /_api/posts` admin-only list.
- `POST /_api/posts` admin-only create/update, validated.
- `GET /_api/public_posts` public read-only listing, published articles only.

## Integration strategy

Existing Astro source imports articles from src/data/articles.ts (and roots-articles.ts). Article route is statically generated by getStaticPaths. To render new posts dynamically choose either scheduled rebuild from public API (SEO-friendly, simple and safe) or Astro SSR endpoints. Do not integrate the API on production until authentication and user acceptance testing. Avoid shipping any Floot preview token, CMS credentials or drafts in public repository.

Recommended long-run: maintain GitHub for source, managed SQL or D1 for content, R2 for media; add backup/export and deterministic migrations before going multi-tenant.

QA gates: login/reset, editor autosave or explicit draft save, slug collisions, publication visibility, XSS-safe rendering, responsive on mobile/tablet, staging rebuild, secrets and authentication, API CORS restrictions, backups. Never merge to main without approval.
